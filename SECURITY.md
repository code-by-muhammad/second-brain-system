# Qualified local security profile

Reviewed 31 October 2026; the FastMCP exception scope is retained from the 29 October review. The Windows release supports the local FastEmbed provider with reranking disabled, loopback MCP and one static local bearer credential. The server checks this configuration before importing Basic Memory, refuses an installed LiteLLM SDK/proxy, and exposes only the six constrained `brain_*` tools. The client verifies the owned listener and rejects non-local destinations, redirects, ambient proxies and OAuth auth objects before transport use.

## Dependency remediation

The locked profile upgrades filelock to 4.2.4, certifi to 2026.10.23, FastEmbed to 0.9.1 and Pillow to 13.0.0. The original audit reported affected versions of all four. See the [filelock releases](https://github.com/tox-dev/filelock/releases), [certifi release](https://github.com/certifi/python-certifi/releases/tag/2026.10.23) and [Pillow security fixes](https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html). Model/vector parity and actual index qualification are separate from successful package resolution.

The transitive `joserfc` dependency is constrained to 1.7.7 for [GHSA-9pg5-8c7x-5hfx](https://github.com/advisories/GHSA-9pg5-8c7x-5hfx), which the live advisory database reported against 1.7.5 on 30 October. The selected release checks compact JWS size before splitting attacker-controlled segments. A bounded split-trap regression and valid/wrong-key HS256 controls cover the upstream behavior. This patch changes neither the retained parent SDKs nor the database schema. Audit receipts record their scan time because advisory data can change independently of the lock.

LiteLLM is deliberately excluded with uv's `exclude-dependencies`; uv 0.9.16 or newer is required. Basic Memory 0.23.2 still declares the SDK in its distribution metadata, so generic `pip check` can report that declaration as unsatisfied. This is an explicit product composition decision, not a supported installation of every upstream Basic Memory feature. The server refuses any non-FastEmbed provider or any enabled/invalid reranker, including the second LiteLLM import path through reranking. Package discovery, proxy-entrypoint absence and actual search are tested. Do not reinstall LiteLLM to silence a metadata warning or run upstream proxy/provider entry points from this environment.

## One scoped advisory exception

The raw dependency audit remains affected by **GHSA-vqqp-x5qm-5qp4** in the FastMCP 4.0.0b1 composition. The exact policy binds `fastmcp` and its matching `fastmcp-slim` package; a scan may report only one of them. This is not a clean audit or a claim that these packages have been patched. The [maintainer advisory](https://github.com/PrefectHQ/fastmcp/security/advisories/GHSA-vqqp-x5qm-5qp4) concerns OAuth machine-to-machine providers whose registered credentials can be sent to a server-advertised authorization server. The qualified product creates no such provider, holds no OAuth client secret/assertion, and permits only its owned loopback static-token transport. Negative tests cover OAuth auth-object refusal, an adversarial 401/metadata advertisement and destination rejection.

`security-exceptions.json` records only that advisory, exact package versions, source hashes and a review deadline of **12 November 2026**. All local `app/*.py` modules, including lazily loaded server modules, and deployment/containment entrypoints are bound alongside the lock and profile tests. The audit gate rejects any other advisory, any malformed/unscanned dependency, expired exception, mismatched profile or changed protected source. It reports raw findings and applied exceptions separately. An exception is limited to this product profile; it does not approve direct use of the vulnerable upstream OAuth providers. The retained FastMCP version is a prerelease; changes to that support profile require review, not a claim of upstream general-purpose support.

Basic Memory 0.24.1 was considered during this review. It changes database migrations and semantic-index code, while the current rollback preserves the existing local database. A broad dependency migration therefore needs a separately tested reversible data-migration design. Re-review this exception before any later Basic Memory change, any authentication/transport change or the deadline. No recurring task or new provider is created by this policy.

## Evidence and limits

Package advisories are not proof of exploitation, and passing tests are not proof of absence of every defect. Keep raw audit output and private runtime diagnostics separate from shared notes. Verify the frozen release, current file/body/vector coverage, native lifecycle/upgrade/recovery, each named client and actual device/reboot receipts at their stated scopes. The Windows candidate does not establish a new macOS/Linux service acceptance.
