# Declared local security profile

Candidate review revision 13 November 2026; the FastMCP exception scope is retained and its deadline was renewed to 12 December 2026 after re-review. The candidate declares the local FastEmbed provider with reranking disabled, loopback MCP and one static local bearer credential. The server checks this configuration before importing Basic Memory, refuses an installed LiteLLM SDK/proxy, and exposes only the six constrained `brain_*` tools. The client verifies the owned listener and rejects non-local destinations, redirects, ambient proxies and OAuth auth objects before transport use.

The separately authorized wiki compiler intentionally sends its selected, screened packet through the Codex/OpenAI CLI. It is not part of the local-only retrieval claim. This candidate requires an explicitly selected native executable, records its observed byte hash, contains its Windows process lifetime and limits private output. Selection/hash recording does not authenticate a publisher or qualify the receiving device. Missing native selection makes no model call; there is no shell-shim fallback. [Operational changes and limits](docs/REVIEW-FOLLOWUP-20261102.md) apply before compilation.

## Dependency remediation

The locked profile upgrades filelock to 4.2.4, certifi to 2026.10.23, FastEmbed to 0.9.1 and Pillow to 13.0.0. The original audit reported affected versions of all four. See the [filelock releases](https://github.com/tox-dev/filelock/releases), [certifi release](https://github.com/certifi/python-certifi/releases/tag/2026.10.23) and [Pillow security fixes](https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html). Model/vector parity and actual index qualification are separate from successful package resolution.

The transitive `opentelemetry-api` dependency is constrained to 1.45.2 for [GHSA-mf5v-w3w3-f6cg](https://github.com/advisories/GHSA-mf5v-w3w3-f6cg), a quadratic-time `traceparent` parsing denial of service published on 13 November 2026 against 1.45.1 and earlier. The resolver moved `opentelemetry-sdk` to 1.45.2 and `opentelemetry-instrumentation` and `opentelemetry-semantic-conventions` to 0.66b2 with it; no product module imports these packages and no other dependency version changed.

The transitive `joserfc` dependency is constrained to 1.7.7 for [GHSA-9pg5-8c7x-5hfx](https://github.com/advisories/GHSA-9pg5-8c7x-5hfx), which the live advisory database reported against 1.7.5 on 30 October. The selected release checks compact JWS size before splitting attacker-controlled segments. A bounded split-trap regression and valid/wrong-key HS256 controls cover the upstream behavior. This patch changes neither the retained parent SDKs nor the database schema. Audit receipts record their scan time because advisory data can change independently of the lock.

LiteLLM is deliberately excluded with uv's `exclude-dependencies`; uv 0.9.16 or newer is required. Basic Memory 0.23.2 still declares the SDK in its distribution metadata, so generic `pip check` can report that declaration as unsatisfied. This is an explicit product composition decision, not a supported installation of every upstream Basic Memory feature. The server refuses any non-FastEmbed provider or any enabled/invalid reranker, including the second LiteLLM import path through reranking. Package discovery, proxy-entrypoint absence and actual search are tested. Do not reinstall LiteLLM to silence a metadata warning or run upstream proxy/provider entry points from this environment.

## One scoped advisory exception

The raw dependency audit remains affected by **GHSA-vqqp-x5qm-5qp4** in the FastMCP 4.0.0b1 composition. The exact policy binds `fastmcp` and its matching `fastmcp-slim` package; a scan may report only one of them. This is not a clean audit or a claim that these packages have been patched. The [maintainer advisory](https://github.com/PrefectHQ/fastmcp/security/advisories/GHSA-vqqp-x5qm-5qp4) concerns OAuth machine-to-machine providers whose registered credentials can be sent to a server-advertised authorization server. The qualified product creates no such provider, holds no OAuth client secret/assertion, and permits only its owned loopback static-token transport. Negative tests cover OAuth auth-object refusal, an adversarial 401/metadata advertisement and destination rejection.

The host-selected Windows `security-exceptions.json` and separate Darwin ARM64/Intel and Linux x64 profile files record only that advisory, exact package versions, source hashes and a review deadline, originally **12 November 2026** and renewed on 13 November to **12 December 2026** (see the re-review below). Its `source_sha256` lists every protected file: all local `app/*.py` modules, the installer/updater/setup helper, dependency declarations/lock, gate and security-profile regression file. CI/test harness and distribution metadata are not themselves advisory-profile source bindings; the shipped release manifest separately binds payload consistency. The audit gate rejects any other advisory, any malformed/unscanned dependency, expired exception, mismatched profile or changed protected source. It reports raw findings and applied exceptions separately. An exception is limited to this product profile; it does not approve direct use of the vulnerable upstream OAuth providers. The retained FastMCP version is a prerelease; changes to that support profile require review, not a claim of upstream general-purpose support.

Basic Memory 0.24.1 was considered during this review. It changes database migrations and semantic-index code, while the current rollback preserves the existing local database. A broad dependency migration therefore needs a separately tested reversible data-migration design. Re-review this exception before any later Basic Memory change, any authentication/transport change or the deadline. No recurring task or new provider is created by this policy.

### Exception re-review, 13 November 2026

The exception was reviewed again after its 12 November deadline and renewed to **12 December 2026** for the same two packages at 4.0.0b1. The advisory is unchanged: it concerns the OAuth client-credentials providers `ClientCredentialsOAuthProvider` and `PrivateKeyJWTOAuthProvider`, and upstream fixed it in FastMCP 4.1.2. Those classes are present in the locked 4.0.0b1 package, but no product module, installer, updater or setup helper references them; the client still refuses any OAuth auth object before an HTTP client is created, and both product transports are built with the static local bearer only. The existing regressions for that (`test_both_product_transport_constructors_have_no_oauth_auth`, `test_oauth_auth_object_is_rejected_before_http_client_creation`, and the redirect/proxy factory test) pass on the reviewed tree. The source binding was rebound for one changed file, `app/brain_mac_registration.py`, whose change is limited to the launchd inventory status column and does not touch authentication or transport.

This renewal is a short bridge, not a resolution. A patched FastMCP exists, so the next step is a separately tested move to 4.1.2 or later with its required MCP SDK, at which point the exception is removed rather than renewed again.

## Evidence and limits

Package advisories are not proof of exploitation, and passing tests are not proof of absence of every defect. Keep raw audit output and private runtime diagnostics separate from shared notes. Verify the frozen release, current file/body/vector coverage, native lifecycle/upgrade/recovery, each named client and actual device/reboot receipts at their stated scopes. No candidate source declaration, model review or dependency audit establishes physical-device or reboot acceptance. All four architecture-specific native audits and the real service matrix must be retained before candidate promotion.
