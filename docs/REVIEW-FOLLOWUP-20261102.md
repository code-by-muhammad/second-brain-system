## Native compiler selection

Only the designated Windows maintainer performs this step. Capture-only devices do not configure a compiler. Inspect the absolute path of an official installed **native `codex.exe`**, its version and `exec --help`. Do not choose `codex.cmd`, `codex.ps1`, a guessed npm vendor layout, or a tool in the runtime, vault, checkout/current directory or Python folder.

```powershell
$brainCodexNative = '<inspected absolute official codex.exe path>'
& $brainPython -B "$brainRoot/app/brain_cli.py" wiki configure-model --executable $brainCodexNative
if ($LASTEXITCODE -ne 0) { throw 'Native compiler selection failed; preserve the receipt' }
```

This writes only the selected path to private `state/wiki-model.json`; it does not run a model or create a schedule. Each actual run checks the plain path again and records the observed executable hash in its private batch. That hash identifies bytes; it does not authenticate their publisher. Missing/invalid selection reports attention before inference, with no PATH or shell-shim fallback. Keep the existing bounded worker and accepted source-selection policy. The selected packet goes to the authorized Codex/OpenAI CLI; local FastEmbed retrieval is separate. The [official CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli) describes stdin, structured output and isolated user-configuration flags; actual installed-version compatibility still needs a receipt.

The Windows model, installer and historical-Git children use private Jobs. Arguments and working directories stay literal. Bootstrap/model execution budgets are 3600/1800 seconds. The wiki runner diagnostic log has a 5,000,000-byte cap; structured `output.json` has a separate 8,000,000-byte read bound before JSON parsing. Derived note publication still requires the 2,000,000-byte UTF-8 bound. An execution deadline is followed by verified lifetime cleanup, without an unsafe second cleanup deadline. No native POSIX compiler acceptance is claimed for v0.1.8.

## Writes, capacity and originals

Client and note replacements recheck the destination after temporary staging, ACL work and fsync. A create operation never overwrites a newly appearing file. Existing-file checks remain cooperative: there is a small check-to-rename window against an editor that takes no locks. Close/checkpoint selected settings editors throughout the write window; this is not OS-level compare-and-swap. A conflict is deferred for review. Backups are staged completely and checked against their content address; a damaged existing backup is preserved and reported.

Every ordinary planned derived output must fit the 2,000,000-byte UTF-8 reader limit before the first publication, including saved-plan verification. Legal character/claim counts alone do not establish byte capacity. Split a growing topic into narrower evidence-backed topics after review. Oversized older saved plans remain held for reconciliation; do not rewrite their private hashes or discard partial publication. Log and archive limits retain their separate contracts. Exact root filenames such as `[[Original]].md` resolve as files before link parsing; ordinary full-path wikilinks still work.

## Index history scope

Bootstrap or explicit retry appends one anchored rule for **64-hex-named** files under `02-Areas/AI-Memory/Wiki/Log-Archives/` to private `state/.bmignore`. This prevents a large legacy compiler archive from blocking all current-note indexing. Owner bytes and a hash-addressed private backup are preserved; concurrent changes and unfinished initial setup are refused. An absent/comment-only ignore file keeps the pinned upstream defaults. Other folders called `Log-Archives` and ordinary filenames in the compiler folder stay in scope. Windows case aliases follow the pinned upstream matcher.

This derived index rule changes neither wiki source-selection exclusions, vault Git rules nor originals. The scope receipt counts generated files and old out-of-scope database entities separately. Existing archive rows can remain searchable: adding an ignore rule is not erasure, and current eligible-note verification does not certify those rows. Do not delete notes, reset SQLite or use ad hoc SQL to purge them. Separate index-retention cleanup requires its own reviewed backup and qualification.

After 256 history records or an oversized prior status, retry returns controlled `state/index-bootstrap-attention.json` and preserves the prior status. Arrange a verified quiet window; archive the exact history directory into a new owner-private dated backup outside the active folder, preserving bytes/permissions and the prior status, then retry. Nothing is deleted automatically. `note_encoding_invalid` and `ignore_encoding_invalid` require read-only diagnosis, never automatic conversion or a silent source skip.

## Update admission and recovery

The forward updater verifies its plain, exact release directory before sibling helpers, state locks or provisioning. Importable untracked controller payloads are refused; benign reports and the disabled old pycache are distinct. Retain independently authenticated tag/commit/manifest checks: local tag consistency cannot authenticate a maliciously rewritten local Git history. Direct software entrypoints require Python `-I`. ACL setup uses the system tool and actual process-token SID, not a current-directory executable or environment account name.

Verified upgrade plans are replaced with non-executable path/hash summaries after preflight; recovery uses its private snapshot. A failed/unverified preflight may leave private evidence requiring attended inspection. Never share those files or snapshots as team material. Previous-controller metadata is published only after the owned hold exists; verified cancellation/rollback restores its earlier binding while refusing concurrent metadata edits.

New-code capture, compilation, maintenance and index writers refuse after taking their work lock while an update is stopped or failed to start. Only explicit updater migration/relink with the exact hold UUID is exempt. Legacy v0.1.7 writers have no such gate, so stop-to-updater handoff is not atomic. Post-stop admission waits at most 300 seconds. If no runtime bytes changed, the updater can restart the unchanged runtime without reacquiring those busy work locks. This is an availability improvement, not a guarantee; preserve actual recovery-required receipts.

Missing lifetime notices, denied queries or ambiguous PID reuse retain ownership and locks. An empty process count alone is insufficient. Preserve the UUID, pending work and private diagnostics; never kill cached PIDs, delete locks or force success. If exact ownership cannot be established, arrange an attended host restart after saving/checkpointing owner work, then recheck identities, admission, source/index status and the recorded transaction. No automatic host restart is authorized.

## Evidence and remaining gates

The MCP health tool returns bounded cached worker metadata and does not inventory the vault or hydrate wiki receipts. Run the explicit `wiki status` command when full compiler queue inspection is needed; that command can hydrate its private derived receipt cache. Health cache reads are capped at 64 KiB for bootstrap state and 1 MB for maintenance state, and SQLite count work has a two-second progress deadline. A corrupt/oversized cache remains intact and reports attention. YAML node/alias composition is capped at 100,000 visits and depth 128 before construction; mapping/numeric budgets still apply separately. The shared public note reader and fresh-file search refuse non-regular source files; on POSIX that reader additionally uses nonblocking opens and an fstat regular-file check. This is not a claim that every history, maintenance or Git streaming path has POSIX FIFO race protection; Windows is the qualified service platform.

The worker cache is limited to 64 KiB. Linked caches, including dangling symlink/junction markers, are refused and report attention. Health preserves expected malformed-cache diagnostics; fatal `MemoryError` and internal `RuntimeError` failures propagate instead of appearing healthy or merely unavailable. A SQLite recursion failure is an internal failure, not decoded metadata. The generic maintenance attention message lists possible invalid/unavailable/oversized causes without exposing the private receipt contents.

Exclusion matching stays exact and case-sensitive. On Windows, a rule that only matches after Unicode case folding is refused before compilation; correct the exact rule spelling through attended review. This is a conservative guard, not an automatic rewrite of exclusions or an exact model of NTFS casing. Inspect policy hash, excluded counts and intended paths before any model batch. Accepted production exclusions are unchanged.

Refresh parses bounded JSON/TOML before comparing decoded managed paths; escaped Unicode/slashes do not establish a different owner. An absent, unowned or unparseable unrelated client file is preserved, with a skipped reason in the receipt. Public sealed plans may address only the actually selected client paths under this host's home or an explicit Desktop override. A plan hash is integrity evidence, not arbitrary write authority. Interrupted fresh installs require every published backend artifact and the exact app at later stages; missing artifacts remain missing and block completion until attended review.

Index bootstrap shares one execution deadline across preflight, traversal, reindex and coverage verification. The traversal checks every entry, including non-notes, with caps of 500,000 entries, 64 MiB aggregate path bytes and depth 128. It reports attention rather than silently truncating. Kernel calls and verified child cleanup can outlast an execution budget. Fresh file fallback search separately limits work to 10 seconds, 10,000 Markdown files and 64 MiB read, and returns explicit partial-scope metadata. These limits do not certify retrieval quality or every excluded/skipped file.

Candidate Git trees are screened before fast-forward checkout and before a successful true merge. A conservative Unicode casefold-prefix collision pauses with both locators and no automatic rename. This intentionally can over-pause names that NTFS itself distinguishes; it is not an exact model of the filesystem case table.

Windows replacement ACLs are restricted to the current token owner and SYSTEM; prior client-file ACL entries are not retained. Review this permission change for intentionally shared settings before setup. Optional `--migrate-wiki` changes derived receipts/pages and queue rows that survive software rollback. Explicit index scope migration and its `.bmignore` backup also persist across software rollback. Rollback restores app/device/client snapshots, not the SQLite database, index-scope files or those derived pages. Preserve migration receipts and inspect current coverage after recovery; do not restore a database blindly.

Incoming Git trees reject symlinks/submodules and local linked-path traversal before checkout. A bounded inventory of **all untracked paths**, including ignored files and nested repositories, checks direct and file/directory-prefix collisions using conservative Unicode NFC/casefold keys. Sharing a directory with an unrelated ignored sibling stays allowed. Existing Windows short-name paths are resolved for collision checks. The preflight has a 90-second cooperative execution budget and a 64 MiB listing cap; a limit or unavailable inventory pauses rather than truncating. Uncooperative external writers can still race after it.

Merges retain `--no-overwrite-ignore` as another guard. That flag alone did not protect the tested true merge on Git 2.51.1 for Windows; explicit preflight is the protection. Automatic true merges use `ort` to match the screened merge-tree result and preserve normal Git hooks. Before checkout a private pending-verification hold is persisted. The final tree and true-merge parents, or exact fast-forward commit, must match before that hold is cleared. An interruption or mismatch leaves every later automatic cycle blocked before staging or publication. No repository configuration is rewritten. Resolve collisions explicitly; do not force checkout, delete an attachment or auto-rename an original.

For a Git review hold, use the configured Python with `brain_cli.py git status`. Inspect the private hold, raw commit diff, parents, hook/configuration cause and originals. Make any deliberate repair and reconcile the upstream yourself; the tool never resets or resolves notes. Re-run status after repairs, then use `git review --head <full reviewed commit> --tree <full reviewed tree> --hold-sha256 <current hold digest>`. The command requires a clean worktree, exact fingerprints and ancestry from the recorded pre-merge commit. It records private review evidence before clearing the hold and does not push. The next normal maintenance pass owns synchronization; a remaining divergence/conflict or unsafe hook can pause again. Missing, linked, corrupt or oversized hold metadata needs attended recovery, not deletion to force a green result. Process interruption is covered; power-loss durability still depends on filesystem rename and Git ref durability.

Every managed Git invocation disables replacement objects without deleting replacement refs. Inspect manually with `git --no-replace-objects show <reviewed commit>`; ordinary Git views can otherwise display replacements that are not transferred in a push ([Git replacement documentation](https://git-scm.com/docs/git-replace)). Legacy graft files are preserved and pause automatic publication for attended recovery. Verification reads the tree and parents of one literal commit hash and pushes that same hash. Uncommitted or staged post-merge hook edits retain the hold. Private hold/receipt privacy on Windows depends on the provisioned state-directory ACL, not POSIX mode bits. Review accepts the inspected state at that time; subsequent deliberate owner commits follow normal source synchronization. Hooks are trusted owner code and can perform actions outside this wrapper.

If legacy grafts exist, attended repository recovery must resolve them before the product's `git status` inspection can return review fingerprints. Preserve the original graft evidence privately. The wrapper does not remove it or infer which history the owner intended. Read-only inspection and review commands do not certify that a manually repaired commit is safe to publish; the owner must review its content, ancestry and intended tracking branch.
