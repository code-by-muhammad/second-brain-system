# v0.2.0 portable hardening candidate

This is a candidate, not deployment approval. Keep the accepted owner installations until the exact source, dependency profiles and native service matrix have independent receipts. Declared candidate hosts: Windows x64, Mac ARM64/Intel and Linux x64. Linux ARM and other Python/service layouts are not qualified by these checks. Fresh Mac/Linux onboarding remains unqualified by this guide; the existing-install update path has its own native receipts.

The candidate carries the v0.1.9 Windows descendant birth-query correction and strengthens durable stop intent: persist the original registration state before disabling it, preserve whether a native stop may have begun across retries, and bind cancellation/restoration to the exact owned registration. macOS uses verified launchd definitions and process identity; Linux uses verified user-systemd definitions and stable boot/start process lifetimes. Ownership uncertainty preserves the hold. No cached-PID kill, forced hold clear or second writer is introduced.

Initial setup resume distinguishes an installed, verified native definition from a currently loaded service. Explicit owner-disabled state remains preserved. Index child cleanup contains its own process group. The update still uses a new verified controller, retained old Python, fresh locked target environment, sealed snapshots/client plans, exact transaction UUID and authenticated expected-version health. Recovery remains bound to its original controller; old active holds cannot be migrated by editing their identities.

The runtime dependencies are unchanged from v0.1.9. Native audit graphs differ by OS and architecture, including the locked Intel Mac ONNX package. Each host selects its exact profile; new advisories, mismatched graphs/source or expired exceptions refuse. The existing FastMCP OAuth exception remains scoped and expires after 12 November 2026 UTC inclusive. It is not a clean-audit claim. See [SECURITY.md](../SECURITY.md).

## Qualification boundaries

The historical manifest field `qualified_service_platforms` is advisory source metadata used for harness admission; it is not completed acceptance. `qualification_status` remains `candidate_pending_external_receipts`. Only the independently checked external qualification report and release decision can promote the candidate.

Required external receipts: exact-source full Windows regression and raw audit; real Windows forward/rollback/recovery; Mac ARM and Intel forward/rollback/recovery on separate disposable hosts; Linux native lifecycle/update/rollback/recovery; guide/helper and shell checks; independent integrated review. Record failed attempts and limitations. Hosted synthetic health is not semantic-index coverage, owner GUI reconnection or a physical reboot. A trusted handover must supply the exact approved commit, manifest and qualification report.

Finish qualification within the existing exception window or obtain a separately reviewed dependency qualification; never extend the date implicitly. After publication independently verify the public tag commit, ZIP payload/manifest and checksum assets against the frozen reviewed source.

The published v0.1.9 README/device guide had an unquoted PowerShell placeholder command. This candidate quotes the fresh-install PowerShell path placeholders; other `text` examples are explicitly schematic, with a PowerShell update invocation in the device guide. The old tag/assets and failed-parser receipt remain preserved.

No original-note, accepted source-exclusion, writer, recurring schedule or maintenance Git ownership changes are part of this release. The compiler remains Windows-maintainer only.
